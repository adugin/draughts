> не измерена против внешней программы — так и написано. Где «улучшение»
> не подтверждено A/B-бенчмарком — оно не улучшение, а гипотеза (правило
> CLAUDE.md, `lessons-learned.md`: «Never commit an improvement without
> numbers»). Уровни сложности — всегда с Elo-числами, измеренными или
> явно помеченными как аспирационные. FMJD/PDN приоритетнее legacy.

## §1. Видение на 2031

> **DRAUGHTS к 2031 — это эталонная свободная программа по русским
> шашкам 8×8: сильнейший общедоступный движок для русских правил,
> с инструментарием анализа уровня Dam 3.0 / lidraughts и обучающим
> контуром, который возвращает игрока каждый день.**

### Позиционирование против лидеров (целевое, 2031)

| Конкурент | Их территория | Где DRAUGHTS их обходит к 2031 | Где сознательно НЕ конкурируем |
|---|---|---|---|
| **Kingsrow** | мировой потолок силы (NN + 8-фигурные базы), но англ./итал./10×10 | **сильнейший движок именно для русских 8×8** + открытый код + кросс-платформенность | глубина 7–8-фигурных баз; 10×10 |
| **Scan** | чистейшая self-play-оценка, 10×10, SMP, питает lidraughts | перенос подхода self-play-оценки на русские правила; нативный десктоп с UX, а не CLI | 10×10-фокус |
| **lidraughts** | онлайн-UX-эталон: пазлы, studies, турниры | **офлайн-сила и приватность**: глубокий анализ без сети, локальные базы, нет латентности; равный по UX анализ | онлайн-инфраструктура мирового масштаба (наш онлайн — опциональный мост, §8) |
| **Windraughts** | единственный серьёзный русско-первый GUI, но закрытый, UI устарел, нет дерева анализа | **современный UX + дерево вариантов + открытость + Elo-честность** | его нишу online-mobile-Elo |
| **Dam 3.0** | зрелый workflow вариаций и аннотаций | паритет по дереву/аннотациям + бесплатно и открыто | 10×10 |

### «Продукт мирового класса» в измеримых терминах (acceptance к июню 2031)

1. **Сила:** движок на максимальном уровне **выигрывает матч у
   Windraughts** (≥ 55% на 100 партиях, контроль 1 мин/ход, через DXP-мост
   или ручной матч) — первое в истории проекта измерение против внешней
   программы по русским правилам. **Подтверждено A/B/SPRT, не «на глаз».**
2. **Честный ладдер:** 8 уровней покрывают **реальный измеренный спред
   ≥ 1000 Elo** (от ~900 до ≥ 1900+), монотонно, подтверждено турниром
   ≥ 100 партий/пара. Метки соответствуют измерению ±75 Elo.
3. **Эндшпиль:** **6-фигурная база** (download) — паритет с серьёзными
   программами; движок играет ≤ 6 фигур безошибочно (регрессионный набор
   ≥ 100 позиций, 0 проигрышей выигранного / 0 проигрышей ничейного).
4. **Оценка:** **обучаемая оценка (NNUE/MLP), self-play-trained**,
   статистически сильнее текущей ручной (SPRT elo0=0 elo1=15, ≥ +30 Elo).
5. **Анализ:** Studies (ветвящиеся, с комментариями пользователя) +
   Opening Explorer — паритет workflow с lidraughts studies офлайн.
6. **Экосистема:** партия играется против внешнего движка через DXP
   end-to-end; PDN/FEN round-trip с lidraughts и CheckerBoard — 100%.
7. **Аудитория:** RU + EN полностью локализованы; ≥ 1 дополнительный
   вариант правил (кандидат — бразильские/международные, §8) — **если**
   ставка пройдёт gate.
8. **Качество:** ≥ 1300 тестов, mypy strict на core+engine, ruff clean,
   bandit без HIGH; release-аудит advisory.

## §8. Долгосрочные ставки (годы 3–5): риски и условия входа (gates)

Каждая ставка имеет **gate** — что должно стать правдой, чтобы ставка
имела смысл. Ставка без пройденного gate **не стартует**.

| Ставка | Потенциал | Gate (что должно стать правдой) | Главный риск | Митигация |
|---|---|---|---|---|
| **G1. NNUE/MLP-оценка** | +30…+100 Elo, путь к мировому классу | self-play-корпус ≥ 10⁶ позиций собирается за разумное время; CPU-инференс не убивает nps | Питон/NumPy-инференс медленный → теряем Elo на time-budget | сначала MLP-lite; измерять ТОЛЬКО на time-budget; держать откат на ручную оценку; рассмотреть C-расширение/ONNX |
| **G2. GPU/распред. обучение** | быстрее итерации обучения | G1 пройдена И обучение на CPU стало бутылочным горлышком | усложнение стека для одного разработчика | опциональный путь; обучение офлайн у автора, пользователю — только веса |
| **G3. 6–7-фиг. базы** | перфектный эндшпиль, паритет с топами | 5-фиг. оправдала Elo/усилие; есть диск+время генерации | дни/недели счёта; сотни МБ–ГБ дистрибуции | генерация у автора (D36); download (D37); перфект-хеш индексация для компактности |
| **G4. Онлайн-мост / мультиплеер** | новая аудитория, ежедневная вовлечённость | DXP client стабилен; есть спрос; не отвлекает от офлайн-силы | «другой продукт» (CLAUDE: multiplayer = отдельный продукт); серверные затраты, модерация | начать с LAN + bot-gateway на чужие платформы; НЕ строить свою инфраструктуру масштаба lidraughts |
| **G5. Другой вариант правил** | x2 аудитории (10×10 — основной мир) | ядро русских правил стабильно; модульность move-gen позволяет вариант без форка | расфокус; русские правила — фундамент (D-уровень) | бразильские 8×8 первыми (близки); 10×10 — отдельный мажор-milestone; не менять русские правила (CLAUDE.md) |
| **G6. Web/mobile-порт** | охват вне десктопа | десктоп-продукт «завершён» (старый принцип «not until desktop is complete») | переписывание UI; PyQt6 не портируется в web | сначала переиспользовать headless-движок (Y3-5) как backend; UI — отдельный тонкий клиент |
| **G7. Hub-протокол (CheckerBoard native)** | плагин в чужой GUI | DXP доказал ценность интеропа | низкий спрос на русских правилах | рассмотреть после DXP-матчей; держать P3 |

## §9. Риски и допущения (сквозные)

| Риск / допущение | Влияние | Митигация |
|---|---|---|
| **Один разработчик** | пропускная способность — главный лимит; XL-ставки растягиваются | строгая приоритизация RICE; download вместо in-app-генерации (D36/D37); агенты-субагенты для волн; модульность (D25/D26) для параллельной работы |
| **Ограничения compute** | NN-обучение и 6–7-фиг. базы упираются в железо | генерация у автора, доставка артефактов (D37); ставки с compute-gate (G2/G3); сначала «-lite» версии |
| **Глубинный плафон тактики** (доказан M8: L3–L5 в пределах 10 Elo) | depth-only scaling не даёт силы/спреда | спред — через позиционные weakening-эвристики (Y1-2); сила — через оценку (G1) и базы (G3), а не глубину |
| **Зависимость от PyQt6** | блокирует web; риск устаревания | движок без Qt (D26, Y3-5) изолирует ядро; UI — сменяемый слой; web-порт переиспользует headless backend |
| **Конкуренты не стоят на месте** (Kingsrow NN 2022, Scan SMP) | разрыв силы может расти | копируем доказанные подходы (self-play eval — Scan; NN — Kingsrow), не изобретаем; ниша русских 8×8 у топов не приоритет — наше окно |
| **Отсутствие публичных русских 8×8 баз** (D38) | нельзя импортировать чужие базы | генерируем свои; публикуем формат (`BITBASE_FORMAT.md`) как кандидат-стандарт — first-mover в пустой нише |
| **«Улучшения на глаз»** | тихая деградация силы (исторический баг fail-hard/soft, 29% blunder месяцами) | **жёсткое правило:** любое изменение `ai/` — только через A/B/SPRT с цифрами в commit; eval-change checklist; xfail-тесты как бенчмарк силы |
| **Регресс при росте фич** | UX-баги в non-default путях (доказано: игра за чёрных и т.д.) | elite-qa после каждой волны; обязательный «play as user with non-default settings»; canonical user-data paths |

## §11. Политика пересмотра (governance документа)

**Каденция:**
- **Ежеквартально (лёгкая ревизия):** сверка факта с планом Года 1–2;
  обновление §0-таблицы (что закрыто), §10-метрик. Длительность — часы.
  Владелец — PO. Артефакт — короткая запись в `M*_REPORT.md`.
- **Ежегодно (полная переоценка, июнь):** пересмотр §3–§7, переоценка
  gate-проверок §8, ребейзлайн метрик §10, обновление видения §1 при
  необходимости. Параллельно — квартальный refresh `RESEARCH.md`.

**Триггеры внеплановой перетряски приоритетов:**
1. **Сила-сюрприз:** матч против внешней программы (Y1-6) даёт результат,
   сильно расходящийся с ожиданием (например, мы уже сильнее Windraughts
   или, наоборот, отстаём на 200+ Elo) → пересмотр T1-ставок.
2. **Compute-сдвиг:** доступ к GPU/серверу появился или исчез → пересмотр
   G2/G3/G7.
3. **Ставка провалила gate** (G1–G7): фиксируем в DECISIONS как новый
   Dnn с обоснованием, переносим ресурс на следующий приоритет.
4. **Внешний игрок меняет ландшафт:** новый сильный открытый русско-8×8
   движок/база, или lidraughts добавляет офлайн → переоценка
   дифференциации §1.
5. **Регресс качества:** elite-qa находит P0/P1 класса «ship-stopper» →
   стабилизация приоритетнее новых фич (правило: «done ≠ shippable»).

**Связь с артефактами PO:** любое решение, меняющее этот roadmap,
оформляется как новое `Dnn` в `.planning/product/DECISIONS.md`;
тактическая разбивка ближайшего года синхронизируется с
`.planning/product/ROADMAP.md`; конкурентные сдвиги — в `RESEARCH.md`.
Этот документ (`docs/ROADMAP_2026-2031.md`) — стратегический слой над
ними, не заменяет их.
